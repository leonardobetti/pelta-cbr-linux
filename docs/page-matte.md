# Page matte

The reader background takes the dominant colour of the page border, so a page
sits on its own paper instead of a grey frame. It is on by default and can be
turned off in Settings → Appearance → "Match page border colour" (GSettings key
`page-matte-detection` in `com.pelta.ComicReader`).

## Detection (`src/matte.rs`)

1. **Proxy.** The page is nearest-sampled to a long side of at most 256 px.
2. **Band.** Pixels within 3% of the proxy's short side (at least 2 px) of the
   outer edges are sampled.
   - For a two-page spread, one matte comes from the outer edges of the
     combined spread: the gutter edges are skipped.
3. **Mode.** A histogram of 5 bits per channel finds the most common colour
   bin.
4. **Median.** The per-channel median of the pixels in that bin and its
   immediate neighbours gives the colour. Including the neighbours stops a
   colour that sits on a bin boundary from being split across two bins.
5. **Confidence.** This is the share of the band within 16 levels per channel
   of that colour. Below `MIN_CONFIDENCE` (0.6) the theme background is kept.
   The comment on the constant gives the rationale and the measured values
   for the fixtures:

   | Case | Confidence |
   |---|---|
   | Paper margin | 1.0 |
   | Full-bleed art | 0.34 |
   | Page cropped into its panels | 0.24 |
   | Grainy dark gradient | 0.39 |
   | Art bleeding off one edge | about 0.75 (keeps its matte) |

**Transparency.** Pixels with alpha below 128 never vote but still count
towards the band. A mostly transparent border shows the theme background
through it, so it falls back to that background.

**Performance.** Detection on a 3000×4500 page takes well under the 5 ms
budget; the test enforces it. Decoding and detection run in
`gio::spawn_blocking`, off the UI thread.

## Applying it (`src/reader_matte.rs`)

- Results are cached per view (page, or spread pair) for the open book. The
  cache is cleared when another book opens.
- A result is applied only if it still belongs to the view on screen, so fast
  page turns never show an older page's colour.
- The colour is set through a CSS provider on the reader, with a 200 ms
  `background-color` transition. GTK does not run CSS transitions when
  `gtk-enable-animations` is off.
- Overlay foreground (the spinner) is dark on light mattes and white on dark
  ones. The switch point is WCAG relative luminance 0.179, where contrast
  against black and against white is equal.
- While the setting is off, no page is decoded for detection. Pending results
  are dropped and the background returns to `--window-bg-color` at once.
